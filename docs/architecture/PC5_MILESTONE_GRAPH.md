The graph is data, and the block at the end of this page is generated from it.
Nothing in this document may disagree with `roadmap.json`: `make roadmap` fails
if the generated block is stale.

## 1. What the graph has to be true about

1. **The destination exists.** `product.destination` names a milestone (today
   `M19`), it must be level 5, and it must be reachable from the roots. A graph
   without a reachable destination is invalid, not merely sad.
2. **The destination cannot be deleted by tidying up.** `product.required_milestones`
   lists the milestones the destination workstream depends on; removing one is a
   validation error.
3. **Every milestone serves the mission.** Each one names its workstream, its
   kind, the success level it advances, and `advances`: one line saying which
   part of the destination it serves. Missing any of them is an error.
4. **Experiments cannot break releases.** Release isolation (ADR-021) replaces
   the former rule that the PS5 work may not be a dependency of the product: an `experimental` milestone may
   not appear in the dependency closure of a `release_gating` milestone of kind
   `infrastructure`, `native-platform` or `governance`.
5. **A complete milestone has evidence, and the evidence exists.** A blocked one
   names its blocker.
6. **Nothing vanishes silently.** `superseded_by` records where a milestone went
   when it was split, and each named milestone must exist.

## 2. Workstreams

Fourteen, from governance (WS0) to product experience (WS13), each with the
success level it serves. WS10 — PS5 platform compatibility — is the destination
workstream; the rest exist because it needs them. The table in
[`PC5_ARCHITECTURE_SPEC_v2.md`](PC5_ARCHITECTURE_SPEC_v2.md) §3 explains why that
is not a bug in the diagram.

## 3. The destination path

`python3 tools/roadmap.py path` prints the longest dependency chain ending at the
destination milestone. It is deliberately the longest chain in the graph: the
product's critical path is the work that reaches the destination, not the work
that produces a lookalike interface. The generated block below prints it.

## 4. States, honestly

| State | Means |
|---|---|
| `complete` | acceptance criteria met, evidence committed, a gate proves it |
| `in_progress` | work started and recorded; acceptance not met |
| `blocked` | cannot proceed; the blocker is named and is not under the project's control today |
| `not_started` | scheduled, owned, not begun |

`blocked` is not a soft `not_started`: `M17`, `M18`, `M19`, `M20` and `M21` are
blocked on the authenticity boundary and on the absence of a lawful input. The
graph says so on every render rather than hiding it in prose.
