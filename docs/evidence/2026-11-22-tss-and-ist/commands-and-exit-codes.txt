Fixture fixes this milestone needed
-----------------------------------

Two test-environment defects surfaced only when the suites were run together, and both are
fixed in this commit because leaving them would have left the combined run unusable:

* `tests/kernel64_machine.py` advertised a memory map whose conventional region
  (0x0-0x9F000) it never mapped. Nothing noticed while no kernel code wrote there; the
  frame allocator now hands a low page to the TSS builder, and 41 of `test_kernel64`'s 71
  tests failed with `Invalid memory write (UC_ERR_WRITE_UNMAPPED) at 0x104e40` - an
  emulator boundary wearing the clothes of a kernel bug. The fixture now maps
  `LOW_CONVENTIONAL` alongside the windows it already provided.
* `tests/test_tss64.py` first reused `tests/test_mem64.py`'s process-wide host region,
  which is a 16 MiB `ctypes` allocation asserted to sit below 4 GiB. That assertion holds
  or fails depending on how much heap the process has already touched, so the TSS suite
  passed alone and failed after `test_mem64` had run and released the region. The suite
  now owns its backing memory through a fixed-address `mmap` with `MAP_FIXED_NOREPLACE`
  and refuses to run at all if the mapping does not land exactly where asked.
