## Why the first run fails, measured rather than assumed

The same recipe at the base commit fails with the identical count, so this is the
environment, not the branch:

    $ rm -rf /tmp/basecheck && git clone --no-hardlinks file:///home/user/pc5 /tmp/basecheck
    $ cd /tmp/basecheck && git checkout 56c58521580e88c4339ceb6eb40ce724a2bb533b

    $ git rev-parse --is-shallow-repository        # in /home/user/pc5 and in the clone
    true                                           # .git/shallow present, 41 B
    $ git merge-base --is-ancestor 9d4a79d refs/heads/main      # cited PR27 head

`/home/user/pc5` is a **shallow** repository and a clone inherits that; a clone also never
copies `refs/remotes/origin/pr/*` (34 of them here). The cited commits are not ancestors of
`main`, so nothing in that clone can reach them. The tool's own output names both causes and
refuses to convert either into a pass — that is the behaviour finding F-1 asked for, and no
line of `tools/commit_citations.py` was edited to obtain this log.
